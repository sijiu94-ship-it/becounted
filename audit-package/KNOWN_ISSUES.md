# 已知问题清单（2026-11-27）

以下问题均经内部审查确认并接受（或已按设计声明）。如审核方认为某条影响被低估，请说明理由。

## Low

1. **区块哈希伪随机可被出块方小幅影响**（V16 draw / _drawWeighted / _randomShare）
   娱乐级定位，种子事前不可知、事后可复算；不适用于大奖池。已在白皮书与提交稿中如实声明。

2. **拼手气领取（claimShare lucky 模式）金额由领取时区块哈希决定**，领取者可挑块提交以小幅优化自己金额；奖池总额守恒，不影响他人应得下限逻辑之外部分。已记录在案。

3. **draw() 的 gas 随参加人数线性增长**：等概率抽奖在约万级人数时单笔开奖可能逼近区块上限；加权抽奖另有每人一次 weightOf 外部调用，上限更低。资金永不锁定——创建者可在 endAt+30 天后 reclaim 全额。

4. **中奖者若为拒绝接收原生币转账的合约钱包，将无法 claimPrize 领取 BNB 奖品**（`_pay` 用裸 `.call{value}`）；窗口过期后份额回到创建者回收范围，资金不丢失。ERC20 奖品同理：不返回 bool 的老式代币会使该活动全部中奖者领取失败——运营规则为链上奖品只用预设 USDT/USDC。

5. **手续费/重基代币的托管偏差**：`_fund` 用转账前后余额增量入账，偏差只影响创建者自己的活动（少记不少付），不跨活动。

6. **中奖信息链接（setWinnerInfo）开奖后已冻结**（V14 起 WinnerInfoLocked）；但冻结只锁链接指针，链接背后的表单内容仍可被创建者修改——防线在前端（详情页显示目标域名 + 常驻防骗提示）。合约头注已写明此边界。

7. **自助登记绑定（proofType 2）在被撤销前 isBindingValid 读为 true**：已接受的信任模型（声明 + 公开可证伪 + 登记员可撤销，撤销留痕）。

8. **绑定签名语句未包含 chainId 与合约地址**：同一「地址+handle」签名可在其他链/合约重放，但重放不产生任何额外权限（绑定关系本身即公开声明），无获利路径。

## Info

9. **条件 1 的 `gateIs721` 字段为保留字段**，合约不读取；ERC721 门槛按 balanceOf 判个数。ERC1155 **不支持**（填 1155 地址的活动将无人能参加）。前端创建时已对 gateToken 做 balanceOf 探测报警。

10. **条件合约地址未做链上存在性校验**（gateToken / questRef 填错 → 活动永久无人可参加）：前端探测缓解，合约层接受。

11. **条件 5 名单叶必须用注册表 `handleOf` 的原始返回值构造**（大小写敏感）；名单工具若用用户自填名字构造会验不过。属工具使用约束。

12. **对不存在的活动 id 调用 setter 会以裸 panic 0x32 回滚**（数组越界），仅影响 UX，无安全影响。

13. **BindingsV4 的 transferRegistrar 仅拦截零地址**：运营纪律为只能转给已证明可正常发交易的地址（登记员权限含撤销权，转错即丢权）。

14. **V16 构造未校验 checkIn_ 地址**：主网实例部署时经部署自检确认指向 CheckInV2 正确地址（0x577b…Ce47）；仅影响未来重新部署时的操作风险。

15. **签到与活动截止全面依赖 block.timestamp**：BSC 出块者对时间戳的影响幅度为秒级，对按天/按截止时刻的业务逻辑无实质影响（Slither timestamp 类 Low 与此对应）。

16. **CheckIn 权重窗口已由 30 天改为 14 天（V2）**：V1 的历史签到不计入 V2 权重，新合约从零开始——已在网站与 Skill 中明示。

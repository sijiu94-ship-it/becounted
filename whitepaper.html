The first boundary shapes even the allowlist. Entry condition 5 (OneIDCampaignsV11) lets a creator restrict a campaign to a list of Agent ID names: the Merkle leaves are hashes of the names themselves, and at entry the contract reads the entrant's own handle from the registry — address → handle, the permitted direction — and verifies the proof against the committed root. The allowlist itself never resolves a name to an address. The allowlist holds identities, never wallets: it stores hashes of names, and not even the creator needs anyone's wallet address. Because the check reads the handle live, the list binds the identity, not an address snapshot — rename away from a listed name and you are off the list.

第一条边界连白名单的形状都决定了。参加条件 5（OneIDCampaignsV11）允许发起人把活动限定给一份 Agent ID 名字名单：默克尔叶是名字本身的哈希，参加时合约从注册表实时读取参加者本人的名字——「地址 → 名字」，是允许的方向——再验其证明与链上根是否对得上；白名单机制本身不做任何「名字 → 地址」解析。白名单里只有身份、没有地址——名单存的是名字的哈希，连发起人也不需要任何人的钱包地址。又因为校验是实时读名字，名单绑的是身份而不是地址快照：改名离开名单上的名字，就等于离开名单。

Agent-native by design: Binance's Agentic Wallet never connects to third-party websites — that is Binance's own design — so holders take part through their own AI agent. The participation Skill, the is-human CLI and the MCP server are the product's front door; this website is the creator console and the public transparency layer, and any ordinary wallet can connect to it. X binding comes in two honestly labelled tiers: a wallet signature (strong proof), and — for Agentic Wallet addresses, which cannot sign arbitrary messages — self-registration: the holder posts their X handle, their Agent ID name and a proof code from their own X account — the post never contains a wallet address — then hands the post link to their own agent, which verifies it (author, exact template, proof code recomputed from the wallet address) and registers the binding on-chain from the holder's own wallet, marked "self-registered". The post's status id is stored on-chain, so the claim is permanently public and falsifiable by anyone; it is weaker than a signature and labelled as such, it can never overwrite a signature binding, registrations are rate-limited to one per address per 24 hours, and the operator's only power over it is revocation of a provably false claim (anchored post missing, or authored by someone else) — every revocation is itself an on-chain, auditable act. No registrar sits in the registration path at all.

Agent 原生是这个产品的设计前提：币安 Agentic Wallet 按其自身设计不直连任何第三方网站，持有人只能通过自己的 AI Agent 参与——参与 Skill、is-human CLI 与 MCP server 才是产品正门；本网站是发起人的控制台与公开透明层，普通钱包可以连接它。X 绑定分两级、如实标注：钱包签名是强证明；Agentic Wallet 地址无法任意签名，走自助登记——本人用自己的 X 账号公开发帖，写明账号、Agent ID 名与 Proof 码（不含钱包地址），再把推文链接交给自己的 Agent，Agent 审核（作者、模板原文、用钱包地址复算 Proof 码）后用本人的钱包上链登记，标注为「自助登记」。推文 ID 存上链存证，这条声明永久公开、任何人可证伪；它比签名弱、如实标注，不得覆盖签名绑定，每个地址 24 小时限登记一次；运营方对它唯一的权力，是撤销可证伪的虚假绑定（存证推文不存在、或作者对不上）——每次撤销本身也是链上可审计的动作。登记环节里没有任何登记员。
